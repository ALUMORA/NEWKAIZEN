# Peticiones de A5

No me faltó ninguna dependencia: el glosario y las páginas de metodología son texto puro, sin
librerías. Lo que sí hay son dos cosas que otros streams tienen que saber antes de consumir el
glosario, y una costura que yo consumo sin tocarla.

## 1. Para C1 (InfoTip) y F5 (Aprender): importen `glossary-lazy.js`, no `glossary.js`

**Necesidad.** El design brief dice que InfoTip "uses src/content/glossary.js when available". Si
ese import es estático y el InfoTip vive en el shell, el glosario entero entra al paquete de la
primera ruta.

**Por qué.** Lo medí con una compilación de Vite en modo librería sobre
`src/content/glossary-lazy.js`:

```
entrada.js                0.47 kB  │ gzip:  0.24 kB
glossary-DHGjAVp8.js    144.79 kB  │ gzip: 46.48 kB
```

O sea que el glosario son **46.48 KB gzip**, el 26 por ciento del presupuesto de 180 KB. El
`npm run build` de esta misma copia deja la primera ruta en `index-TLc0SSHu.js`, 338.45 kB con
**107.78 KB gzip**, así que importar el glosario de forma estática desde el shell la sube 43 por
ciento de un jalón, y en la pantalla de mercados nadie lo va a leer.

**API propuesta**, ya implementada en `src/content/glossary-lazy.js`, todas devuelven promesas y
nunca truenan:

```js
import { loadTip, loadTerm, searchGlossary, loadAllTerms } from '../../content/glossary-lazy.js'

// InfoTip: cargar cuando se abre el globo, no al montar.
const tip = await loadTip('sharpe')
// → { slug, titulo, corto, href: '/aprender/sharpe' }  o null si no existe

// Página /aprender/:termino
const term = await loadTerm(params.termino)   // GlossaryTerm o null
// Índice de /aprender
const todos = await loadAllTerms()            // ordenados por título
// Buscador y ⌘K
const hits = await searchGlossary(texto, { limit: 8 })
```

Cuando `loadTip` devuelve null, el componente usa su prop de texto, tal como dice el brief. El
chunk se descarga una sola vez por sesión: la promesa queda guardada.

Si de plano necesitan una versión síncrona y chiquita para el primer render (solo `titulo` y
`corto` de un puñado de métricas), pídanmela y la genero como archivo aparte en `src/content/`. No
la hice por adelantado para no tener dos fuentes de la misma frase.

## 2. Para quien pinte `/aprender`: el formato de las páginas de metodología

`docs/metodologia/*.md` son 11 archivos de Markdown plano, sin frontmatter, pensados para
renderizarse tal cual:

- El **título** de cada página es su primer `# `.
- El **resumen** es el primer párrafo, antes del aviso.
- El **aviso** de que no es recomendación de inversión va siempre en el segundo párrafo.
- La última sección, `## Términos relacionados en el glosario`, es una lista de slugs separados por
  comas. Se puede convertir en ligas a `/aprender/<slug>` sin parsear nada más.
- `README.md` es el índice, con una tabla de las diez herramientas.

Una prueba en `src/content/glossary.test.js` revisa que esos cuatro puntos se cumplan en los 11
archivos y que todos los slugs citados existan en el glosario, así que el formato no se va a ir
moviendo por debajo.

Si prefieren consumirlos como datos en vez de leer el disco en tiempo de compilación, díganme y les
dejo un `src/content/metodologia.js` que los importe con `?raw` y exponga `{ slug, titulo, resumen,
markdown }`. Hoy no existe porque no sé todavía si F5 los va a servir desde el build o desde el API.

## 3. Costura que consumo sin tocar: `src/app/paths.js`

`glossary.js` importa `pathLearnTerm` de `../app/paths.js` (de S2) para armar la liga de cada
término, en lugar de repetir la ruta `/aprender/:termino` en dos lados. Es un import de solo
lectura y no edito ese archivo. Si la firma de `pathLearnTerm(termino) => string` cambiara, se
rompe `glossaryHref` y `glossaryTip`, y su prueba lo cacha de inmediato.
