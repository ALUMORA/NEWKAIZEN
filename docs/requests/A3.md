# Peticiones de A3 (rng, Monte Carlo y metas)

Nada bloqueó el trabajo: todo lo que A3 necesitaba ya existía en el worktree. Lo que sigue son
dos cosas para el merge, no pendientes.

## 1. Exportar los módulos nuevos desde `src/lib/finance/index.js` (dueño: A1)

`src/lib/finance/index.js` es de A1, así que A3 no lo tocó. Mientras no se agreguen ahí, las
features importan directo del archivo, que también funciona:

```js
import { simulate, lognormalParams, quantilesOf } from '../../lib/finance/montecarlo.js'
import { probabilityOfGoal, requiredContribution, retirementIncome } from '../../lib/finance/goals.js'
import { createRng } from '../../lib/rng.js'
```

Si A1 o el orquestador quieren el barril completo, estas son las exportaciones:

- `src/lib/rng.js`: `createRng`, `hashSeed`, `DEFAULT_SEED`
- `src/lib/finance/montecarlo.js`: `simulate`, `lognormalParams`, `perStepParams`, `quantilesOf`,
  `toMessage`, `fromMessage`, `handleWorkerRequest`
- `src/lib/finance/goals.js`: `probabilityOfGoal`, `requiredContribution`, `retirementIncome`

`montecarlo.worker.js` NO va en el barril: es un punto de entrada de Web Worker y tiene que
quedarse fuera del grafo del bundle principal.

## 2. `quantilesOf` se traslapa con `quantile` de A1 (para el dedupe del orquestador)

El spec le da a A1 `quantile(sorted, q)` en `stats.js`. A3 necesitaba los cinco percentiles a la
vez y SIN ordenar (360 pasos por 10,000 trayectorias; ordenar en cada paso no cabía en el
presupuesto de 400 ms), así que `montecarlo.js` trae su propia selección múltiple y expone
`quantilesOf(values)`, que devuelve `{p5, p25, p50, p75, p95}` de una muestra desordenada.

Los dos usan cuantil tipo 7, así que dan lo mismo; se pueden unificar dejando `quantilesOf` como
la versión rápida de varios cuantiles y `quantile` como la de uno solo sobre un arreglo ya
ordenado. Las pruebas de A3 comparan `quantilesOf` contra `numpy.percentile` y contra ordenar e
interpolar a mano, así que el dedupe se puede hacer sin miedo.
